# ScreenStream 升级到 gstack 1.21.1.0 后的技能优先级与使用说明

日期：2026-05-01

## 优先顺序

1. `plan-eng-review`
   - 用于方案锁定、架构边界、数据流、测试口径和风险收敛。
   - 本仓库在写计划、改协议、收敛模块边界前优先使用。

2. `review`
   - 用于已有 diff 的合入前审查，重点看结构性风险、条件副作用、回归面和安全边界。
   - 在准备合并、发 PR 或进入落地前优先使用。

3. `qa-only` / `gstack`
   - 用于真实设备或浏览器驱动的回归验证与结果留档。
   - 只有设备端 HTTP 服务可访问时才进入。

4. `benchmark`
   - 用于页面加载、资源体积、Core Web Vitals、性能回退对比。
   - 只有性能相关改动或需要建立、更新基线时启用。

## 本轮状态

- 本轮已经实际执行了 `plan-eng-review`。
- 后续如果出现实现性变更，再按上面的顺序推进 `review`、`qa-only` / `gstack`、`benchmark`。

## qa-only / gstack 前置条件

当前暂不直接执行 `qa-only` / `gstack`，原因是缺少运行中的设备 HTTP 服务。

最小前置条件：

- 有一台运行中的目标设备，已启动 ScreenStream 设备端 HTTP 服务。
- 该服务在当前网络中可访问，gstack/browse 能直接打开目标地址。
- 设备和服务状态足够稳定，能够完成一次完整的页面或接口检查。

如果上述条件不满足，只做离线检查、静态审查和文档整理，不进入真实 QA 流程。

## 触发时机

- `review`：当已有可比较的 diff，且准备合入主分支、发 PR 或发版时。
- `benchmark`：当变更可能影响加载、渲染、资源大小、交互延迟，或需要证明没有性能回退时。
- `qa-only` / `gstack`：当需要对真实运行链路做端到端验证、截图留档或复现实机问题时。
